# Ссылки — что исправлено в v55

Версия `2.11.0`, выпуск `universal-embedded-v55`, сборка `2.11.0.0`.
База — v54 (`ПОСТАНОВЛЕНИЯ_v54.md`, `README.md`). Тесты — `tests/test_v55_links.py`.

Замечание: «Мне нужно чтобы ты всегда и только всегда использовал ссылку,
которая используется при первичном запуске, никаких вторичных если первичная
не работает».

---

## 1. Единственный адрес приложения

В коде был не один адрес, а два: рабочий (`https://google.com/ai`) и резервный
(`https://gemini.google.com/app`), на который приложение само переходило, если
считало, что страница «не та». Теперь адрес ровно один и он же — адрес
первичного запуска.

```python
# config.py
CHAT_URL = "https://google.com/ai"   # единственный адрес приложения
```

| Место | Было | Стало |
|---|---|---|
| `main.py` | `URL = "https://google.com/ai"` | `URL = CHAT_URL` |
| `native_browser.py` | `DEFAULT_URL = "https://google.com/ai"` | `DEFAULT_URL = CHAT_URL` |
| `qt_browser.py` | `HOME = "https://google.com/ai"` | `HOME = CHAT_URL` |
| `smoke_browser.py` | `QUrl("https://google.com/ai")` | `QUrl(CHAT_URL)` |

Литералов адреса в коде больше нет: смена домена делается одной строкой в
`config.py`, и все точки входа получают новый адрес.

## 2. Автоперехода нет

Удалено:

* `SURFACE_FALLBACK_URL` — второй адрес;
* `AUTO_CORRECT_SURFACE` — разрешение на автопереход;
* `self._surface_corrected` — признак «уже переходили»;
* вызов `Page.navigate` из `_on_upload_blocked`.

`_on_upload_blocked` теперь только сообщает о сбое:

```python
def _on_upload_blocked(self, info):
    diag.event("upload.blocked_no_fallback", files=..., verdict=...)
    self._set_status("Файлы не прикрепились. Адрес страницы не меняется — "
                     "приложите файлы ещё раз или перезапустите приложение.")
```

То есть при сбое прикрепления **страница остаётся той же**, что была открыта
при запуске: никакой второй ссылки «на всякий случай» нет.

## 3. Остальные адреса страницу не открывают

| Адрес | Где | Зачем остался |
|---|---|---|
| `https://accounts.google.com` | `main.py`, выдача прав | только `Browser.grantPermissions` для микрофона и камеры; страница по нему не открывается |
| `https://consent.google.com` | `main.py`, вердикты поверхности | только распознавание окна согласия |
| `http://127.0.0.1:<port>` | `main.py`, `native_browser.py` | служебный CDP/DevTools своего же браузера |
| `https://googlechromelabs.github.io/chrome-for-testing/` | `browser_fetch.py`, `tools/fetch_chrome.py` | скачивание портативного Chrome, а не навигация |
| `dejavu-fonts.github.io`, `scripts.sil.org/OFL`, `paratype.com/public`, `github.com/googlefonts/caveat` | `data/*LICENSE*.txt` | лицензии шрифтов, обычные текстовые файлы |

## 4. Устав: адрес-реквизит не нужен

В `data/reestr/Устав Los Santos County Sheriff Department.json` есть поля `url`
и `norm_url` (`forum.majestic-rp.ru/threads/…`). Приложение их не читает и
никуда не открывает: устав приходит в чат **файлом `.pdf`** из папки программы
и прикладывается к запросу вместе с заявкой. Адрес оставлен в базе только как
исторический реквизит источника.

## 5. Проверки

`tests/test_v55_links.py` — 11 тестов:

* `config.CHAT_URL` — ровно `https://google.com/ai`;
* `main.URL`, `native_browser.DEFAULT_URL`, `qt_browser.HOME`,
  `smoke_browser.QUrl` — берут значение из `config`, литералов нет;
* в коде нет `SURFACE_FALLBACK_URL`, `AUTO_CORRECT_SURFACE`,
  `gemini.google.com/app`;
* `_on_upload_blocked` не содержит `Page.navigate`;
* все `Page.navigate` идут на `URL`/`self.url`/`url`, не на литерал-адрес;
* `accounts.google.com` остаётся в списке выдачи прав микрофона;
* `data/reestr/*.json` читается как обычные данные, браузерные модули про
  `reestr` не знают;
* README и этот файл упоминают правило одной ссылки (`CHAT_URL`).
