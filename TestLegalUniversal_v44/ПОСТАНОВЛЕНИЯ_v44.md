# Постановление Прокурора — v44

Версия 44 — отдельная папка. Ниже — что исправлено относительно v43.5.

## v44 — двойная отправка заявки и «свой» ответ вместо ответа ИИ

Разбор отчёта `Постановление_44` и сессии `20261109-145359-16532-54c702`.
Замечание: «в чат с ИИ экспортировало 2 сообщения, при чём первое даже не
успело обработаться ИИ».

### 1. Два сообщения подряд — одна заявка уходила дважды

Из лога:

```
11:54:29.080  pending_send.ready           present=3  names=[pdf, шаблон, заявка]
11:54:30.145  pending_send.sent            ← ПЕРВАЯ отправка (отложенная)
11:54:30.150  attachments_confirmed        complete=false  ← сброс состояния
11:54:30.498  upload.attempt pdf           файлы выгружаются ЗАНОВО
11:54:31.869  attachments_confirmed        complete=true
11:54:31.870  documents.auto_send          ← ВТОРАЯ отправка того же текста
11:54:32.580  documents.auto_sent
```

Причина: после отправки поток вложений сбрасывал подтверждение
(`complete=false`), заново выгружал файлы и, «вспомнив» их, вызывал
автоматическую отправку — той же заявки. Отложенная отправка и авто-отправка
не знали друг о друге.

Исправлено:

* **один признак на заявку** — `_request_key()` (имя файла + размер + начало
  текста). Отложенная отправка ставит его **до** отправки, авто-отправка
  видит и молчит (`documents.skip_duplicate_send`);
* в том же диалоге файлы **не выгружаются повторно**
  (`pending_send.files_already_attached`): если вложения уже подтверждены и
  браузер не перезапускался, выгрузка не начинается;
* дедупликация вложений больше не сбрасывает подтверждение, пока заявка ждёт
  отправки (`_keep_attachments`).

### 2. В дело попадал текст страницы, а не ответ ИИ

В `cases/1/case.json` из отчёта:

```
status: refused
intake_basis: ""                       ← пустое основание
intake_answer: "Перейти к основному контенту … Чат в режиме ИИ: ЗАЯВКА …"
```

Что было не так:

| Дефект | Как проявлялся |
|---|---|
| `JS_READ_ANSWER` при отсутствии селекторов возвращал `document.body` | в «ответ» попадала вся страница вместе с шапкой |
| заявка содержала те же строки, что и ответ (`===ПРОВЕРКА ОБРАЩЕНИЯ===`, `Состояние:`, `===КОНЕЦ ПРОВЕРКИ===`) | своя заявка читалась как готовый ответ |
| разбор брал первое упоминание «Отказано» | в заявке перечислены все состояния → «Отказано» с пустым основанием |

Исправлено:

* **JS**: читаются только блоки ответа (`message-content`,
  `.model-response-text`, `.response-container`, `model-response`); текст
  пользователя (`user-query`, `.query-text`, `user-message`) ответом не
  считается; `document.body` как запасной источник **убран**;
* **заявка больше не содержит маркеров ответа**: формат описан словами, без
  `===ПРОВЕРКА ОБРАЩЕНИЯ===` и без шаблона «Состояние: …»;
* **разбор** (`_is_state_menu`) пропускает строки-перечисления вариантов
  («укажи одно: Принято, Отказано…», «(для отказа обязательно…)») — они
  описывают формат, а не выносят решение;
* **дело ищется по тексту обращения**, а не по тексту заявки:
  `pending_send.build_record(..., appeal_text=...)`, `_gov_intake_appeal`;
* **ответ должен быть новым**: `JS_CHAT_TEXT_LENGTH` замеряет объём чата до
  отправки (`_doc_watch_base_len`), и «ответ», не прибавивший текста,
  отбрасывается (`documents.answer_not_new`);
* своя заявка отсекается **до** любого разбора
  (`documents.skip_own_request`, `gov.intake.own_request`).
