# v58 — шлюз экспорта в чат ИИ: чипы вложений и кнопка «Отправить»

Версия `2.14.0`, выпуск `universal-embedded-v58`, сборка `2.14.0.0`.
База — `TestLegalUniversal_v57`; старые папки не изменялись.

Замечания пользователя по четырём дампам страницы ИИ (`Загрузка.txt`,
`После загрузки.txt`, `Ошибка загрузки.txt`, `Удалить.txt`):

> «Если при экспорте файлов в чат с ИИ один из них ещё не загрузился, то есть
> кнопка отправки недоступна, то ожидать кнопку отправки и только тогда, когда
> она сменит состояние на активное, то отправлять запрос… во всех случаях, когда
> ты что-либо экспортируешь в чат с ИИ. А если имеется хоть одна ошибка в
> экспортируемом файле, то удалить файл и заново его загрузить (логика
> автодогрузки при отсутствующих файлах уже имеется)».

## 1. Что показал разбор дампов

Состояние одного и того же файла `Memphis.pdf` в трёх дампах:

| Признак | Загрузка | После загрузки | Ошибка загрузки |
|---|---|---|---|
| класс хоста чипа | `gcB4oc **oacyne**` | `gcB4oc` | `gcB4oc **bGkj2b**` |
| значок в чипе | — | — | **`div.rUmyzd`** (восклицательный знак) |
| подпись под именем | — | — | **`div.oIIrVc`** = «При загрузке произошла ошибка» |
| `div.zXgSbc` (крестик удаления) | есть | есть | **есть** |
| `data-progressvalue` | `0` | `0` | `0` |
| кнопка «Отправить» | `IbS5tc wdK4Nc`, `tabindex="-1"` | без них, `tabindex="0"` | `IbS5tc wdK4Nc`, `tabindex="-1"` |

Четвёртый дамп (`Удалить.txt`) — состояние наведения на удаление: у хоста
`gcB4oc XYXmld` и `aria-label="Удалить Memphis.pdf"`, сам чип ещё в чате.

Выводы:

* **крестик `div.zXgSbc` и `data-progressvalue="0"` есть во всех состояниях** —
  старая проверка «есть крестик → файл прикреплён» могла подтвердить файл,
  который вообще не загрузился. Это была реальная причина отправки запроса
  без вложений;
* **ошибка выглядит как загрузка** по состоянию кнопки (та же
  `IbS5tc wdK4Nc`, тот же `tabindex="-1"`), поэтому ошибку надо проверять
  ОТДЕЛЬНО и раньше ожидания кнопки;
* **активная кнопка «Отправить»** — единственный признак, отличающий «ИИ
  принял файлы» от «ещё грузится / сломалось».

## 2. Новые правила — `upload_gate.py`

Модуль без Qt и CDP: состояние подаётся словарями, правила проверяются тестами.

| Правило | Значение |
|---|---|
| ожидание активной кнопки | `SEND_BUTTON_TIMEOUT = 20` секунд (решение пользователя) |
| подтверждение ошибки | `ERROR_CONFIRM = 2` замера подряд (антидребезг) |
| попыток «удалить → прикрепить заново» | `CHIP_ERROR_RETRIES = 3`, затем перезагрузка браузера |
| перезагрузок чата | `RELOAD_RETRIES = 2` |
| опрос страницы | `POLL_SECONDS = 0.25` |
| пустой чат | не повод ждать и не повод перезагружать: ориентир — только вложения |
| запрос без вложений | не отправляется никогда |

Порядок проверки (`should_send`):

1. есть подтверждённый чип с ошибкой → **удалить только его** и дать
   автодогрузке прикрепить заново;
2. файл ещё грузится (`oacyne`) → ждать;
3. кнопка «Отправить» неактивна → ждать, до 20 секунд;
4. не все обязательные файлы загрузились → ждать догрузки;
5. всё на месте → отправлять.

## 3. Что изменено в коде

**`upload_gate.py` (новый)** — все правила выше плюс тексты для строки
состояния (`status_text`, `blocked_text`).

**`main.py`:**

* `JS_CHECK_FILES` переписан: отдаёт `chips = [{name, uploading, error}]`,
  `errors`, `present`. Загрузка — класс `oacyne`; ошибка — `div.oIIrVc`,
  `div.rUmyzd` или класс `bGkj2b`. Крестик больше не означает «готово».
* `JS_SEND_BUTTON` (новый): классы, `tabindex`, `disabled`, `aria-disabled`
  кнопки «Отправить».
* `JS_REMOVE_CHIP` + `remove_chip()` (новые): точечное удаление одного чипа по
  имени — «используй логику из „Удалить.txt“, то есть удалить файл… логика
  автодогрузки при отсутствующих файлах уже имеется».
* `check_state()` отдаёт `chips`, `errors`, `send`.
* `wait_send_button()` (новый): ждёт активную кнопку до 20 секунд.
* `_try_send_pending()` — решение об отправке принимает `ugate.should_send`;
  при ошибке чипа вызывается `_handle_chip_error`, при неактивной кнопке —
  ожидание, после 20 секунд — `_reload_for_upload_retry`.
* `_handle_chip_error()` — удалить сломанный чип, сбросить `pdf_attached`,
  дать автодогрузке вернуть файл; после 3 попыток — перезагрузка.
* `_reload_for_upload_retry()` — мягкая перезагрузка страницы ИИ (без
  убийства браузера), не больше 2 раз, затем остановка с сообщением.
* Поток загрузки: чип с ошибкой выкидывается из `names`, поэтому файл
  считается отсутствующим и прикрепляется заново (`upload.chip_error_seen`).
* `JS_STOP_AND_SEND`: **убрана принудительная разблокировка кнопки**
  (`el.disabled = false`, `removeAttribute('disabled')`,
  `aria-disabled = 'false'`) — клик только по реально активной кнопке,
  иначе `{ok: false, reason: 'disabled'}`.
* Ожидание активной кнопки добавлено в три места отправки:
  `pending_send` (`pending_send.send_blocked`), `_auto_send_document_request`
  (`documents.send_blocked`), «Проверка обращения» (`gov.intake.send_blocked`).

**Журнал (новые события):** `upload.chip_error`, `upload.chip_removed`,
`upload.chip_error_seen`, `upload.chip_retries_exhausted`,
`upload.reload_retry`, `upload.send_button_timeout`, `upload.send_blocked`,
`pending_send.send_blocked`, `documents.send_blocked`, `gov.intake.send_blocked`.

## 4. Что видит пользователь

* «ИИ принимает файл… 7 с» — пока идёт загрузка;
* «Ждём, пока ИИ примет файл (кнопка „Отправить“ ещё неактивна)… 12 с» — если
  кнопка всё ещё закрыта;
* «ИИ не принял файл — удаляю его из чата и прикрепляю заново (попытка 2)» —
  при ошибке чипа;
* «Чат не принял файлы — перезагружаю страницу ИИ и повторяю» — после 3 неудач;
* «ИИ не принял файл: запрос без вложений не отправляю. Проверьте соединение и
  повторите «Сформировать»» — финальная остановка.

## 5. Проверки

`tests/test_v58_upload_gate.py` — 28 тестов:

* чип в загрузке и чип с ошибкой блокируют отправку; ошибка подтверждается со
  второго замера;
* крестик `zXgSbc` больше не участвует в определении готовности (проверка по
  тексту `JS_CHECK_FILES`);
* дубли чипов склеиваются (на три файла Google отдаёт шесть узлов);
* кнопка: блокировка по классам `IbS5tc`/`wdK4Nc`, по `tabindex="-1"`, по
  `disabled` и `aria-disabled`; отсутствие кнопки — не «готово»;
* таймаут ровно 20 секунд; после 3 неудач — перезагрузка, лимит 2;
* запрос без вложений не отправляется; пустой чат не считается ошибкой;
* принудительная разблокировка удалена из `JS_STOP_AND_SEND`;
* ожидание кнопки стоит во всех трёх местах отправки;
* `_try_send_pending` использует `ugate.should_send`, `_handle_chip_error`,
  `_reload_for_upload_retry`;
* версия `2.14.0` и релиз `universal-embedded-v58`.

Обновлены под новое поведение: `tests/test_chat_ready.py`
(`test_send_waits_for_gate` — теперь «ворота» в `upload_gate`),
