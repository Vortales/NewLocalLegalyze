# v62 — три этапа, три цепочки и два поля

Версия `2.18.0`, выпуск `universal-embedded-v62`, сборка `2.18.0.0`.
База — `TestLegalUniversal_v61` (2.17.0); старые папки не изменялись.

## Согласованное ТЗ (ответы пользователя на вопросы перед разработкой)

| Вопрос | Решение |
|---|---|
| Состояния этапа 1 | ровно три: принятие / отказ / переадресация. «Недостатки» и «прекращение» отдельными решениями больше не нужны: обращение, которое не идёт в работу, — это отказ |
| Этап 3 | без подэтапов: ИИ сам выбирает вид завершения по смыслу обращения, ответа этапа 1 и всех пройденных подэтапов (суд, завершение производства, санкция, прекращение); прокурор может поправить и пересобрать |
| Кнопки «Сформировать» | своя в каждом блоке: этап 1, выбранный подэтап 2.N, этап 3 |
| Индикатор PNG | только информация: «PNG сформирован / не сформирован», переход она не блокирует |
| Поле 1 и поле 2 | поле 1 — ввод прокурора (правится), поле 2 — ответ ИИ (только чтение, показан как документ). Правка поля 1 после ответа помечает его устаревшим и блокирует переход к следующему подэтапу |
| Что уходит в ИИ | текст обращения + поле 1 (текущее — целиком, пройденные ≈600 знаков) + поле 2 всех пройденных этапов и всех цепочек |
| Цепочки этапа 2 | минимум три варианта в одном ответе; прогресс каждой цепочки сохраняется; ИИ знает прогресс всех |
| Порядок | строго по порядку, но цепочку можно пересобрать: ручной порядок согласуется с ИИ, выполненные подэтапы не трогаются |
| Окно «Обстоятельства» | отдельное окно, открывается вместе с формой, скрывается/возвращается кнопкой |
| Старые вкладки | «Постановление» и «Обстоятельства» удалены вместе со старыми списками этапов |

Моё возражение, принятое пользователем: **поле 1 убирать нельзя.** Поле 2 — это
уже переработанный вывод ИИ; если отправлять только его, ИИ видит лишь свои
прошлые заключения и теряет то, что знает только прокурор. Поэтому поле 1
отправляется всегда, но у пройденных подэтапов — сокращённо.

## Что изменено в коде

* **Новый модуль `ogp_stages.py`** (без Qt): три состояния этапа 1, разбор
  блока цепочек, индексы узлов («1», «2.N», «3»), подписи кнопок и кнопок
  «Сформировать», состояние узла (можно ли отправить/печатать, устарел ли
  ответ), контекст всей цепочки для ИИ, «человеческий» вид ответа для поля 2.
* **`gov_case.py`** — поля `work_chains` (варианты цепочки со своими узлами),
  `work_letter`, `work_nodes` (этапы 1 и 3), `work_custom_order`;
  методы `use_chain`, `apply_chains`, `work_node`, `set_work_node`,
  `set_node_input`, `apply_new_order`, `set_custom_order`; новые заявки
  `node_request()` и `reorder_request()`. Старое дело (v60–v61) открывается как
  единственный вариант «A», его шаги становятся узлами.
* **`postanovlenie_prokuror_ui.py`** — вкладки «Обращение» / «Цепочка этапов» /
  «История»; новый блок «Цепочка этапов» (три этапа, выбор варианта, ручной
  порядок, три кнопки «Сформировать»); окно «Обстоятельства»; главная кнопка
  отправляет узел в ИИ и больше не печатает документ.
* **`main.py`** — ответ ИИ записывается в узел цепочки; `_print_gov_node()`
  печатает .png по кнопке «Сформировать» в папку своего узла; ответ на
  «калибровку порядка» применяет новый порядок; этап 1 раскладывается в три
  состояния и варианты цепочки.
* **`postanovlenie_prokuror_data.py`** — рабочих состояний этапа 1 три,
  устаревшие распознаются для старых дел (`GOV_INTAKE_LEGACY_STATES`).

## Промт 1.33 (новый файл, 1.32 не изменялся)

## v62.1 — исправление краша при открытии формы

Лог сессии `20261125-151551-4292-0d0c1d` показал, что окно «Постановление
Прокурора» падало при открытии:

```
NameError
  main.py 5734  <lambda>
  main.py 5880  _open_postanovlenie_prokurora
  postanovlenie_prokuror_ui.py 376  __init__
  postanovlenie_prokuror_ui.py 458  _build
  postanovlenie_prokuror_ui.py 822  _build_chain_tab
```

Причины — два пропущенных имени в `postanovlenie_prokuror_ui.py`:

1. модуль `ogp_stages` использовался в `_build_chain_tab`, но не был
   импортирован (в v61 его не существовало, импорт забыли при переписывании
   вкладки);
2. разбор ответа ИИ вызывался как `pgov.parse_gov_answer(...)`, а в этом
   модуле данные подключены как `gdata` — имени `pgov` нет.

Исправлено: добавлен `import ogp_stages`, оба вызова переведены на `gdata`.
Добавлен регрессионный тест `ImportGuardTests` (`tests/test_v62_ogp_stages.py`):
он разбирает все модули через `ast` и падает, если встречает `имя.атрибут` для
имени, которого нет среди импортов и определений. Прогон по всей папке
показал, что других таких пропусков нет. Полный прогон — **1112 тестов, OK**.

## v62.2 — второй краш: сетка реквизитов

Следующий лог `20261125-164215-20408-bd3bec` («Документы → Постановления
Прокурора» → «Новое обращение») дал ту же картину, но в другом месте:

```
NameError
  main.py 5734  <lambda>
  main.py 5880  _open_postanovlenie_prokurora
  postanovlenie_prokuror_ui.py 377  __init__
  postanovlenie_prokuror_ui.py 463  _build
  postanovlenie_prokuror_ui.py 508  _build_requisites
```

`_build_requisites` переворачивался на сетку (`QGridLayout`), потому что
надписи налезали друг на друга, — а сам `QGridLayout` в импорт
`PyQt6.QtWidgets` не попал. `py_compile` такой код пропускает: имя
синтаксически корректно и падает только при вызове, то есть при построении
окна.

Исправлено: `QGridLayout` добавлен в импорт `QtWidgets`.

Чтобы третий раз не ловить это вручную, `ImportGuardTests` расширен:
раньше он проверял только `имя.атрибут` (случай `ogp_stages`, `pgov`), теперь
проверяет **все** читаемые имена (`ast.Name` в `Load`-контексте) и требует,
чтобы каждое было импортировано или определено в файле. Проверка на откате
(искусственно убранный `QGridLayout`) показывает, что тест падает —
то есть именно этот краш теперь отлавливается автоматически. Добавлены
`test_qt_widgets_used_by_form_are_imported` и проверка отсутствия `pgov.` в
форме. Полный прогон — **1113 тестов, OK** (17 skipped).

## v62.3 — третий краш: комбобоксы, которых больше нет

Лог `20261125-194436-20848-ebcda6` («Документы → Постановления Прокурора» →
«Новое обращение»):

```
AttributeError
  main.py 5734  <lambda>
  main.py 5900  _open_postanovlenie_prokurora
  postanovlenie_prokuror_ui.py 1931  new_case
  postanovlenie_prokuror_ui.py 1509  _fill_types
```

Причина: в v62 вкладки «Постановление» и «Обстоятельства» заменены одной
«Цепочкой этапов», поэтому комбобоксы этапа (`cb_stage`) и вида решения
(`cb_type`) форма больше не создаёт. Код на них, однако, продолжал
ссылаться — в `_fill_types`, `_select_stage`, `_on_stage_changed`,
`_stage_kind`, `_collect`, `set_document`, `refresh_document`. Заметить это
было нечем: `py_compile` проходит, проверка импортов тоже — имя
синтаксически верное и падает только при вызове.

Исправлено:

1. **Этап — из узла цепочки.** Добавлена `gov_case.stage_kind_for_node()`
   («1» → первичное решение, «2.N» → санкция по существу, «3» → итог), а
   `_stage_kind()` берёт активный узел (`_active_node_kind`). Второго
   источника этапа в форме больше нет.
2. **Вид решения — из ответа ИИ.** `_collect()` берёт `doc_type` из
   документа (ответа), `set_document()` и `refresh_document()` просто
   сохраняют его; `_fill_types()` осталась точкой совместимости и ничего не
   трогает.
3. **Убраны мёртвые методы и ссылки**: `_toggle_extra` (панели `extra_panel`
   в форме нет), обращение к `work_hint` (подсказки удалены в v62).
4. **Новый регрессионный тест** `test_no_references_to_missing_widgets`:
   собирает все атрибуты, которые форма создаёт или объявляет, и требует,
   чтобы читались только они (унаследованные от `QDialog` перечислены явно).
   Проверка на откате (возвращённый `self.cb_type`) показывает, что тест
   падает. Плюс `test_new_case_does_not_touch_removed_combos`.
5. Семь старых тестов (`test_postanovlenie`, `test_v49_remarks`) проверяли
   удалённую вкладку — переписаны под v62: проверяют справочник видов
   решений и то, что комбобоксов в форме нет.

Полный прогон — **1115 тестов, OK** (17 skipped). Папка лога удалена после
разбора.
