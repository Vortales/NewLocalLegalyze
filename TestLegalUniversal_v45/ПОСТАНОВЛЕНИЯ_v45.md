# Постановление Прокурора — v45

Отдельная папка. Предыдущая версия — `TestLegalUniversal_v44` (не меняется).

## v45 — «Сформировать»: PNG постановления не создавался

Замечание пользователя: «"Проверка ИИ" всё ушло и отлично прошло, обращение
висит как "Отказано", но при нажатии кнопки "Сформировать", чтобы сделать
Постановление об отказе, он не создаёт .png файл». Ответ ИИ в чате при этом
был (постановление AG-2 об отказе в принятии обращения).

Разбор ответа ИИ показал: сам ответ разбирается правильно, PNG из него
строится. Значит, ответ до разбора не доходил — и причин оказалось три.

### Причина 1. После «Сформировать» ответ вообще никто не читал

Опрос чата включался в одном месте — после отправки заявки, но только для
«Проверки ИИ»:

```python
if ok:
    self._pending_send_finish(psend.STATE_SENT, record)
    if kind == "intake":          # ← только «Проверка ИИ»
        self._watch_document_answer()
```

Заявка на постановление уходит с `kind="document"`, поэтому после неё опрос не
запускался: ИИ отвечал в чат, а клиент чат не читал. PNG не печатался — и
никакого сообщения об ошибке тоже не было.

**Исправлено:** опрос включается после ЛЮБОЙ успешной отправки заявки
(`_watch_document_answer()` без условия). Тот же вызов добавлен в
`_auto_send_document_request`: авто-отправка может сработать позже, когда
окно формы уже закрыто.

### Причина 2. Дело искалось не то

Номер дела заполнялся только для «Проверки ИИ»:

```python
if str(record.get("kind") or "") == "intake":
    self._gov_intake_case = str(record.get("case_number") or "")
```

Документ по «Сформировать» сохранялся в НОВОЕ дело (`store.next_number()`):
PNG уходил в чужую папку, а в списке обращений появлялся дубль.

**Исправлено:** `_doc_case_number` берётся из записи для любого вида заявки,
и разбор документа ищет дело по нему (а не по «последней проверке»).

### Причина 3. В отказе печаталась фраза о вменяемом нарушении

В «УСТАНОВИЛ» документа об отказе появлялось «Указанные обстоятельства
образуют нарушение: пункта 14 части 1 статьи 16 Регламента …». Это норма
ОТКАЗА, а не состав: пункт 14 части 1 статьи 16 как раз говорит, что в
принятии отказывают.

**Исправлено:** в решениях без вменяемого нарушения (отказ в принятии, отказ
в удовлетворении, прекращение производства, завершение проверки) «Пункт
нарушения» и «Нарушенный акт» в этот вывод не попадают вовсе. Для этапа
санкции фраза остаётся.

Попутно: если ИИ не прислал вид решения, а в резолюции «в принятии …
отказать», предлагается «Об отказе в принятии обращения к рассмотрению» —
раньше мог получиться заголовок о принятии при резолюции об отказе.

### Проверено на ответе из замечания

Ответ AG-2 разбирается полностью: номер, дата, прокурор и удостоверение,
заявитель и ID, нарушитель и удостоверение, отдел, дата события, нарушенный
акт, пункт, нормативное основание, «УСТАНОВИЛ» и три пункта «ПОСТАНОВИЛ».
`render_document` печатает PNG, `save_pages` сохраняет файл в папку этапа
дела: `<выбранная папка>/AG-2/этап-1 — принятие/AG-2 — эт.1 принятие — стр.1.png`.

## v45.1 — «Сформировать»: ответ есть, но считается нашей заявкой

Лог `20261109-161442-5868-df44a7`, файл «Скопированный ответ ИИ по
Сформировать ответ.txt». В чате документ есть, PNG не печатается.

В журнале каждые 2,5 секунды:

```
documents.skip_own_request chars=35790
```

То есть клиент ЧИТАЛ ответ, но считал его нашей собственной заявкой.
Причина — примета «заявка на постановление» в списке «фраз, которые бывают
только в заявке». Но ответ ИИ начинается с ЦИТАТЫ заявки (в чате он виден
вместе с вложением «Заявка (отправлено в чат).txt»), и примета срабатывала на
настоящем документе.

### Что ещё нашлось при проверке этого ответа

| Проблема | Как проявлялась |
|---|---|
| примета «заявка на постановление» решала сама | настоящий ответ отбрасывался целиком (`skip_own_request`) |
| блок документа начинался с цитаты заявки | в «ПОСТАНОВИЛ» попадали пункты обращения («Данные о заявителе…», «Ксерокопия…») |
| ИИ написал «УСТАВНОРИЛ» | весь раздел «УСТАНОВИЛ» пропадал из документа |
| «Постановление вынес: Jonathan Raine» принималось за маркер | проверка писала «не указано, кто вынес постановление» |
| перенос строки внутри пункта | один пункт резолюции становился двумя |
| строка «Основание: …» в конце | попадала в резолюцию как ещё один пункт |
| подпись прокурора | приклеивалась к последнему пункту |

### Как исправлено

`is_own_request` переписан: порядок проверок — от надёжных признаков к слабым:

1. текст совпадает с заявкой → заявка;
2. в тексте есть сам документ («УСТАНОВИЛ» / «ПОСТАНОВИЛ» / «КОНЕЦ
   ПОСТАНОВЛЕНИЯ») → это ОТВЕТ, даже если он цитирует заявку;
3. заявка внутри текста → решает остаток (документ есть → ответ);
4. текст начинается заголовком «ЗАЯВКА НА ПОСТАНОВЛЕНИЕ ПРОКУРОРА» и строкой
   «Данные для подготовки документа» → заявка;
5. блок проверки обращения → ответ;
6. служебные пометки заявки → заявка.

Дополнительно:

* `extract_document_block` при цитате заявки начинает блок с заголовка
  «ПОСТАНОВЛЕНИЕ» + «Ведомство:» (`_document_body_start`), поэтому пункты
  обращения в резолюцию не попадают;
* `_normalize_heading` понимает опечатки заголовков («УСТАВНОРИЛ»,
  «ПОСТОНОВИЛ») — раздел фактов больше не теряется;
* строка «Постановление вынес: …» распознаётся как ПОЛЕ, а не как маркер
  документа — автор, должность и удостоверение снова в документе;
* перенесённые строки пункта склеиваются, подпись и «Основание:» в резолюцию
  не попадают.
