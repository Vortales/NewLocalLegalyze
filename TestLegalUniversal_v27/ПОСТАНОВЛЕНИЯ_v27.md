# Постановления v27 — что уже работает и каких данных не хватает

Документ описывает, как устроена новая функция и **что нужно от вас**, чтобы
бланк стал юридически точным, а не «похожим на пример».

---

## 1. Как это работает сейчас

```
«Документы» → «Постановление»
      ↓
форма (данные из Шаблон.txt подставляются сами)
      ↓ «Сформировать»
ПОСТАНОВЛЕНИЕ LSCSD-IAD-141.txt  ─┐
Шаблон.txt                        ├─ три вложения в чат → автoотправка
PDF промта (promt 1.11)           ─┘
      ↓ ИИ отвечает по триггеру
===ПОСТАНОВЛЕНИЕ=== … ===КОНЕЦ ПОСТАНОВЛЕНИЯ=== … ===КОНЕЦ ОТВЕТА===
      ↓ разбор полей
LSCSD-IAD-141.png (A4, 200 dpi, многостраничный)
      ↓
история: postanovleniya/*.json — открыть, поправить, сформировать заново
```

Файлы:

| Файл | Что делает |
|---|---|
| `postanovlenie_data.py` | данные документа, разбор ответа ИИ по триггерам, история, чтение устава |
| `doc_render.py` | рендер A4 в PNG (герб, печать, подпись, страницы) |
| `postanovlenie_ui.py` | форма-конструктор (данные / история / предпросмотр) |
| `main.py` | кнопка «Документы», третье вложение, автoотправка, приём ответа |
| `data/gerb_lscsd.png`, `data/stamp_lscsd.png` | герб и печать LSCSD |
| `data/reestr/*.json` | устав, по которому проверяется пункт нарушения |
| `data/fonts/` | сюда кладётся рукописный шрифт для подписи |

Промт: `Для новой версии/Текущий промт/promt 1.11.txt` (это 1.10 + раздел
`[6. РЕЖИМ ПОСТАНОВЛЕНИЯ]`). Промт 1.10 не изменён.

## 2. Чего не хватает — по пунктам

### 2.1 Образец бланка ведомства (важнее всего)

В папке `Постановления IAD/` лежат **не бланки, а описания скриншотов**
(`1.txt … 6.txt`) — по ним собран макет. Для точного совпадения нужен:

* пустой бланк LSCSD IAD (PNG/PDF/DOCX) **или** скриншот целого постановления
  в хорошем разрешении;
* регламент отдела внутренних расследований LSCSD (в законодательной базе
  есть только устав департамента и примеры LSPD IAD).

Пока бланка нет, документ рисуется «с нуля» по описанию: герб, шапка, дата/номер,
заголовок, преамбула, три пункта, печать, подпись. Это корректно по смыслу, но
точные отступы и шрифт оригинала могут отличаться.

### 2.2 Реквизиты для шапки

Сейчас в `Шаблон.txt` есть `Name`, `ID`, `Fraction`, `Rang`, `Department`,
`JobTitle`. Для бланка добавлены **необязательные** поля (окно «Шаблон»):

* `RankTitle` — звание словами (например, `Major`);
* `PositionFull` — полное наименование должности;
* `Authority` — ведомство, от имени которого выносится документ;
* `DocPrefix` — префикс номера (`LSCSD-IAD`);
* `City` — город.

Нужно подтвердить: **какие именно реквизиты обязательны** в вашем ведомстве и в
каком порядке они идут (например, нужен ли «город» и «дата» в одном блоке,
нужна ли ссылка на заявление/рапорт как основание).

### 2.3 Нумерация

Сейчас номер предлагается как «максимальный в истории + 1» с префиксом из
шаблона (`LSCSD-IAD-141`). Скажите, если нужна другая логика: сквозная
нумерация по ведомству, отдельная по типу взыскания, или номер вводится вручную
из журнала.

### 2.4 Кто имеет право подписывать

В уставе: IAD может налагать взыскания вплоть до руководителя департамента
(гл. III), перечень взысканий — гл. IV п. 4.1. Но **не указано, какие
должности IAD подписывают постановления** (только начальник отдела? его
заместитель?). Сейчас подпись берётся из поля «Кто выносит» без проверки.

### 2.5 Перечень взысканий

Форма предлагает список из устава: предупреждение, устный выговор, строгий
выговор, переаттестация, понижение, увольнение. В примерах LSPD IAD
используется «выговор». Подтвердите, что для LSCSD нужно использовать именно
перечень устава — и в какой формулировке («строгий выговор» или «выговор»).

### 2.6 Другие ведомства

Архитектура универсальная, но для Военной полиции / Прокуратуры нужны:

* свои герб и печать (PNG с прозрачным фоном);
* свой устав/регламент (JSON в `data/reestr`);
* свой перечень взысканий и формулировки пунктов;
* решение: одна форма с выбором ведомства или отдельные шаблоны.

### 2.7 Рукописный шрифт для подписи

В песочнице нет доступа в интернет, поэтому сейчас подпись рисуется наклонным
DejaVu Serif — «K. Goldens» получается аккуратным, но не рукописным.
Положите любой `.ttf` (Caveat, Great Vibes, Marck Script, Segoe Script) в
`data/fonts/` — код подхватит его сам, править ничего не нужно.

### 2.8 Кто сочиняет текст постановляющей части

Сейчас есть два режима: ИИ присылает пункты в ответе (приоритет), а если их
нет — конструктор собирает три стандартных пункта (взыскание / вступление в
силу / контроль). Скажите, какой вариант предпочтителен как основной.

## 3. Ограничения, которые известны и не скрываются

* Проверка «пункт есть в уставе» понимает формат LSCSD — «3.1», «4.1»,
  «10.6» (в уставе нет статей и частей). Если номер не найден, форма честно
  пишет «в уставе не найдено» и не подставляет норму сама. Для актов с другой
  нумерацией (например, «пункт 19) части 1 статьи а») проверка тоже работает,
  но требует, чтобы текст статьи был загружен в `data/reestr`.
* Автoотправка сообщения использует вставку текста в поле ввода страницы
  (`Input.insertText`) и ту же кнопку отправки, что и микрофон. Если
  поверхность сервиса изменится, отправку можно сделать вручную — заявка уже
  вложена в чат.
* История хранится локально в `postanovleniya/` рядом с `config.json`;
  ничего никуда не отправляется.
